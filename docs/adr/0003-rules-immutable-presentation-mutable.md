# 规则层纯函数、表现层可变，两层分离

游戏状态拆成两层。**规则层**（血量、分数、连击、FEVER、怪物生命周期与移动、生成与结算）用纯函数维护，状态不可变，随机数来自可注入的带种子 PRNG（mulberry32），因此完全可复现、可单测。**表现层**（粒子、刀光残影、冲击环、飘字、屏幕震动、挥击动画）用可变对象维护，逐帧原地更新，不进入 React 渲染路径。

**为什么**：规则层不可变才能写单元测试，证明重构没有改变游戏行为；表现层的粒子上限 260 且每帧更新，若做成不可变会每秒产生约 1.5 万个临时对象。两层分离是同时拿到"可测试性"与"60fps"的唯一解法。

**后果**：

- React 只订阅规则层派生出的 HUD 快照，并且只在相关数值变化时才通知 —— 沿用旧实现 `source.html:461-462` 的脏检查思路。
- 战场渲染器消费同一份只读快照；表现层状态随快照一起传入，但不由 React 持有。
- 规则层的每帧推进通过 `tick(state, dt, rng) -> state` 完成，状态存放在 ref 中而非 React state，避免 60fps 触发 React 协调。

**现状**（2026-10）：两层分离已落地。规则层在 `src/game/`（纯函数、不可变、带种子 PRNG），表现层在 `src/presentation/`（可变、粒子上限 260，与旧实现一致）。React 只订阅 `hudStore` 派生的 HUD 快照，脏检查沿用旧实现思路。规则层状态存放在 ref 中 —— 端到端检查实测 HUD 的 DOM 变更由"值变化"驱动而非帧驱动（静置 1782 帧 / 27 次变更，操作 1747 帧 / 81 次变更）。
