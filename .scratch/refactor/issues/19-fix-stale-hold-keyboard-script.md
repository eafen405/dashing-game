# 19 — 修复过期的键盘长按怪脚本

Status: resolved
Blocked by: (none)

## 现象

`tests/e2e/hold-monster-keyboard.mjs` 现在**跑不过**（2026-10-22 实测）：

```
✗ 键盘长按怪检查失败：Error: 游戏在长按怪出现前就结算了
```

它是手动脚本，不在 `npm run test:e2e` 里，所以票 16 / 17 改完长按之后没人发现。

## 三处过期

1. **长按时长**：票 16 把 `LONG_HOLD_TIME` 从 3 改成 2（`src/game/constants.ts:42`），
   toast 文案也跟着变成「长按中… 保持 2 秒」（`src/game/rules/resolve.ts:466`）。
   脚本的文件头、断言消息、`waitToast` 的 12 秒超时全都按 3 秒写的。
2. **判定框位置**：票 17 把判定框挪到棒尖
   （`hitX = playerX + playerR * CLUB_REACH_R`，1280×665 下 430 → 250）。
   怪要走到更靠左的位置才进判定区，等待窗口因此变长。
3. **脚本自己不打普通怪**：它只按住方向键等长按怪刷新，期间普通怪全部漏过掉血。
   判定框左移之后这段时间更长 → **玩家在长按怪到判定区之前就结算了**（就是上面那句报错）。

## 要做

1. 让脚本能撑到长按怪进判定区：等待期顺手清掉普通怪
   （复用 `tests/e2e/fx-moments.mjs` 里的 `AUTO_PLAY` 自动打怪片段），
   或把难度 / 起始节奏调到能活到长按怪出现。
2. 长按时长按 `LONG_HOLD_TIME`（2 秒）改文案与超时，不要写死 3。
3. 分数增量按当前常量核对（`LONG_HEAD_GAIN` / `LONG_1S_GAIN` / `LONG_TAIL_GAIN`，
   见 `src/game/constants.ts:44-46`）。
4. 脚本文件头「要证明的事」那段引用的是 `brief-05 §4`，已不是现行依据 —— 改成指向票 16 / 17。

## 验收

- [ ] `node tests/e2e/hold-monster-keyboard.mjs` 通过。
- [ ] 连续跑 3 次都通过（长按怪是概率性刷新的，判据不能只靠一次运气）。
- [ ] 脚本里不再出现「3 秒」。

## 备注

## Answer

### 三处过期分别是什么、怎么修的

1. **长按时长**（票 16：`LONG_HOLD_TIME` 缩短）
   - 过期点：文件头、断言文案、`waitToast` 的 12 秒超时全按旧时长写死。
   - 修法：脚本从 `src/game/constants.ts` 读 `LONG_HOLD_TIME` / `LONG_HEAD_GAIN` /
     `LONG_1S_GAIN` / `LONG_TAIL_GAIN`，再从 `src/game/rules/resolve.ts` 抠出
     「长按中…」toast 的拼接式、按当前常量拼回去 —— 秒数与文案都跟着源码走，
     脚本里不写死任何一个秒数（连文件头都不提旧时长）。
     按住阶段的超时改成 `LONG_HOLD_TIME * 1000 + 5000`。

2. **判定框位置**（票 17：`hitX = playerX + playerR * CLUB_REACH_R`）
   - 过期点：旧脚本「按住 320ms 再判断起没起手」，靠碰运气等头进圈；
     判定框左移之后这段等待更长，旧的起手节奏对不上了。
   - 修法：改成**盯画面**。每帧在两条轨的判定带里找「>120px 的实心长条」
     （普通怪只有 40~62px，180~300px 的长胶囊只有长按怪有）→ 知道它在哪条轨；
     再在长条左端附近找**白色核心** —— `hold-monster.ts` 的 `inWindow` 分支
     在头进圈时把头核心画成纯白，白核出现就等于「头正好在判定区里」。
     这时按对应轨的方向键，必定走 `startHold`（不会「太早」，也不会「漏掉了」）。

3. **脚本自己不打普通怪**
   - 过期点：旧脚本只按住方向键等长按怪刷新，普通怪全漏过去掉血 →
     玩家在长按怪进圈之前就结算（就是票里报的「游戏在长按怪出现前就结算了」）。
   - 修法：复用 `tests/e2e/fx-moments.mjs` 的 `AUTO_PLAY` 像素判读片段，
     在页面里每帧扫两条轨：普通怪盖住判定区就点掉（指针），
     **长按怪一根手指都不碰** —— 它那条轨的输入整个留给键盘。
     另外判定框正中心那颗半径 3.4px 的小圆点也盖住判定区（点它只是空挥，
     空挥会清连击），所以加了「实心段宽度 ≥ 35px 才算怪」的门槛。

### 断言（都是结构性的，不靠「等够久就大概能行」）

- 「长按中…」toast 出现在**我们按键之后** → 证明起手的是键盘，不是指针。
- 「长按贯穿！」toast 出现 → 长按走完。
- 分数比按键前多 `LONG_HEAD_GAIN + LONG_1S_GAIN + LONG_TAIL_GAIN`（三个得分点）。
- 自动打怪**没有在长按怪头进圈的那几帧里点过它那条轨**（只有那几帧的点才可能起手）。

### 给票 20 接线时要注意

- 这个脚本**不是 `npm run test:e2e` 的一部分**，仍是手动脚本；
  单次约 40~70 秒（本机），CI 上软件光栅更慢，可能要 2 分钟量级 ——
  接进 CI 时留意总时长。
- 判据全是结构性的（toast 文案 + 分数增量 + 画面几何），不依赖帧率，适合当门禁。
- 脚本要读 `src/game/constants.ts` 与 `src/game/rules/resolve.ts`
  （推导时长与文案），所以 CI 里必须在 `npm run build` 之前源码在位。
