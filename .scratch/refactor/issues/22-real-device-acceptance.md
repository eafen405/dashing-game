## 背景

到今天为止，下面这几项**一条都没有被验证过**：

- 票 08 / 09 的 Answer 里都留着「实机 60fps 待用户确认」；
- `spec.md:38` 写着「Firefox / Safari 未在本机验证（Playwright 缓存里只有 Chromium），留待实机阶段」；
- 票 15（手机长按不再弹浏览器菜单）与票 16（长按 2 秒）都只在本机无头环境验过，
  没在真实手机浏览器里验过。

**这一票必须由人做**（手机 / 真实浏览器）。机器跑出来的数字不能代替 ——
SwiftShader 是软件光栅，它测出的 11–13 FPS 不是产品性能。

- **票 01–21 全部完成**，已合入 `feat/refactor-v2`（票 21 的文档收口已完成）。

- **机器能验的都验过了**：typecheck / lint / 360 个单测 / build / golden trace 门禁
  / 6 个端到端脚本 / 6 个视觉验收脚本，在本机全绿。

  机器代替不了（票 20 的视觉验收验的是「特效长什么样」，不是「在手机上跑不跑得动」）。

## 要做（逐条签字，共 5 条）

1. **手机横屏 60fps**：用 `dist/index.html` 在手机浏览器打开（横屏），
   开 FPS 挂件（`?debug`），持续出刀 2 分钟，确认稳定 60fps、不掉帧。
2. **长按手感（2 秒贯穿）**：长按怪按住 **2 秒**贯穿，确认：
   - 手机浏览器**不弹**「标记广告」/ 选词菜单（票 15）；
   - 按住 2 秒期间角色有连续挥棒反馈；
   - 松手太早 → 怪自逃、连击清零 —— 这是设计，不是 bug。
3. **棒尖手感**：木棍真的**够得到**怪 —— 上轨跳起打怪、下轨落地跑，
   确认「打中」是木棍真的敲中了怪，而不是隔空出刀。
4. **棒尖判定框**：判定框落在**棒尖攻击范围**里（票 17 的 `hitX = playerX + playerR * CLUB_REACH_R`）。
5. **浏览器兼容**（`spec.md:38` 的遗留）：
   - Firefox 桌面打开 `dist/index.html` 跑一局；
   - Safari（macOS / iOS）同上；
   - 若某个浏览器起不来，记录具体现象（黑屏 / 无 WebGL / 滤镜异常）。

**规则**：任何一条不过 → **开一张新票**记录，**不要**在本票里顺手改代码。
