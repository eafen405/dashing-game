# 18 — 修复 CI 红：`hud-stats` 的隐含帧率断言

Status: resolved
Blocked by: (none)

## 现状

`origin/feat/refactor-v2` @ `cf3051b` 的 CI **是红的** ——
[run 39773140165](https://github.com/eafen405/dashing-game/actions/runs/39773140165)
的「端到端检查」步骤失败，`npm run trace` 步骤被跳过。

`handoff.md` 与票 10 的 Answer 都写着「CI 全绿」，与事实不符。失败点只有一个：

```
✗ HUD 统计检查失败：Error: 断言失败：静置 30 秒跑了 410 帧（确实在跑）
```

## 根因

`tests/e2e/hud-stats.mjs:134`：

```js
assert(a.stats.publishes > 600, `静置 30 秒跑了 ${a.stats.publishes} 帧（确实在跑）`);
```

这条断言**名义上**判「游戏循环在跑」，**实际上**是一条**帧率下限**
（600 次 / 30 秒 = 20fps）。判据绑在「跑测试那台机器有多快」上，与被测代码无关。

- 票 08 之前默认渲染器是 Canvas 2D；票 08 之后是 Pixi/WebGL。
- CI 跑在 GitHub 的 `ubuntu-latest` 上，WebGL 走 SwiftShader **软件光栅**。
- 实测（2026-10-22）：CI 上 30 秒只有 **411 帧（≈13.7 FPS）**；
  本机同一条命令有 **876 帧（≈29 FPS）**。`publishes` 与 `frames` 几乎相等
  （CI：410 / 411），因为 `hudStore.publish()` 本来就是每帧调一次
  （`src/app/hud/hudStore.ts:124`）。
- 410 < 600 → 红。

补充事实：同一条断言在 `c7a7bcd`（默认渲染器还是 Canvas 2D）时 CI 是**绿的**
（[run 39606233508](https://github.com/eafen405/dashing-game/actions/runs/39606233508)），
`cf3051b` 变红 —— 渲染路径切到 WebGL + 场景变重（地面 / 角色 / 木棒）之后，
软件光栅撑不住 20fps。**但这不改变结论**：判据本来就不该跟机器速度挂钩。

## 与 ADR-0004 冲突

`docs/adr/0004` 写死：「开发期只提供一个轻量的 FPS / 帧时挂件作为观察手段，
**CI 不做性能断言**」。当前这条断言就是性能断言。

## 要做

1. 把 `publishes > 600` 改成**结构性**判据（判「循环在跑」，不判「跑多快」）：
   - `publishes > 0` —— 循环没冻；
   - `publishes >= frames * 0.9` —— 每帧发布一次（这是**结构**，与机器速度无关）；
   - 绝对下限放到任何环境都够得着的高度（例：30 次 / 30 秒 ≈ 1fps），只当「没冻」的保险丝。
2. 通读 `hud-stats.mjs`，把其余**绝对帧数**判据一并改成相对判据。
3. 在文件头写清楚这条判据的**意图**：「证明 HUD 不随帧重渲染」是结构判据，
   「跑多快」不是 CI 的职责（ADR-0004）。现在的注释容易让人以为 600 是随手写的。
4. 本机复跑 `npm run test:e2e` 确认通过。

## 验收

- [ ] `npm run test:e2e` 本机通过。
- [ ] 人为把阈值调到远高于本机帧率（例如 5000）时，**不再**因帧率不足失败 ——
      证明判据已经与机器速度解耦。
- [ ] CI 在 `cf3051b` 上重新变绿，且 `npm run trace` 步骤不再被跳过。
- [ ] 代码里能看出遵守了 ADR-0004 的「CI 不做性能断言」。

## 备注

- **不要**为了「让 CI 绿」去优化 SwiftShader 下的帧率 —— 那是软件光栅的固定成本，
  与真机性能无关，ADR-0004 已明确拒绝基准循环。
- 本票是**合并到 `main` 的前置条件**（票 21）。

### 根因

旧断言（`tests/e2e/hud-stats.mjs`）：

```js
assert(a.stats.publishes > 600, `静置 30 秒跑了 ${a.stats.publishes} 帧（确实在跑）`);
```

名义上判「循环在跑」，实际是一条**帧率下限**（600 次 / 30 秒 = 20fps）——
判据绑在「跑测试那台机器有多快」上，与被测代码无关。CI 的 WebGL 走 SwiftShader
软件光栅，30 秒只有 411 帧（≈13.7fps），`publishes` 410 < 600 → 红。

本票实测补一条事实：**这条断言在本机也是悬的**。票 18 原文记的是本机 876 帧（≈29fps），
2026-10-22 本机复跑只有 524 帧（≈17.5fps）、跑整套 e2e 时甚至 380 帧（≈12.7fps）——
照样 < 600，旧码**在本机也会红**（12.7fps 正是 CI 的量级）。
所以它不是「CI 专属问题」，是一条会随机器负载浮动的判据。

### 新判据（结构性，与机器速度无关）

抽出 `assertLoopAlive(label, m)`，场景 A / B 各调一次，三条判据：

1. `publishes > 0` —— 循环没冻；
2. `publishes >= frames * 0.9` —— **每帧发布一次**（结构：页面自己的 rAF 计数器与
   游戏会话的 rAF 同频，快慢都一样；实测比值 838/839、834/835、108/109）；
3. `publishes >= MIN_PUBLISHES`（= 30，30 秒 ≈ 1fps）—— 「没冻」的保险丝，
   任何环境都够得着（CI 约 13.7fps，本机约 25fps）。

**本文件里已无任何绝对帧数判据**。其余判据本来就是相对量，未改动：
`domMutations < frames * 5%`、`renders < frames * 5%`（静置）、
`domMutations < frames * 20%`、`renders < frames * 20%`（操作）、
`domMutations < clicks * 3`。

文件头补了一段说明，讲清两件事：(1) 本脚本要证明的是**结构**（「HUD 不随帧重渲染」），
不是速度；(2) 「跑多快」不是 CI 的职责（ADR-0004），以及 600 当初为什么是错的 ——
免得下一个人以为那是个随手写的数。汇总里加了一行
「帧率参考（**观察值，不是判据**）」，把 FPS 明确降级为观察量。

### 改动文件

- `tests/e2e/hud-stats.mjs` —— 判据换掉 + 文件头说明 + FPS 观察行。

**解耦证明 —— 同一台机器、同一档降速，旧码 vs 新码。**
用 CDP `Emulation.setCPUThrottlingRate` 把渲染进程降速 2×（≈3.6fps）：

| 代码 | 场景 A 结果 |
| --- | --- |
| 旧（`publishes > 600`） | ✗ `断言失败：静置 30 秒跑了 108 帧（确实在跑）` |
| 新（结构性判据） | ✓ 109 帧 / 108 publish，三条判据全过 |

降速 4×（≈3.7fps）时新码场景 A 同样全过（110 帧 / 109 publish）。
**帧数比旧阈值低 5–6 倍仍然通过** —— 判据已经与机器速度解耦。

**「把绝对下限调到远高于本机帧率（5000）」的实验**：

- 当作判据（保险丝提到 5000）→ ✗ `静置 30 秒：30 秒只 publish 了 524 次（低于「没冻」保险丝 5000 次 ≈ 1fps）`；
- 同一个 5000 **只观察、不判定** → ✅ 脚本仍然通过（838/839、834/835）。

即：**绝对帧数已经不再决定脚本的判定**。留在代码里的那个 30 是「循环没冻」的保险丝，
故意放在 1fps 这种任何环境都够得着的高度 —— 把它抬到 5000 就等于把帧率断言请回来，
那正是本票要消灭的东西。

### 备注（交给编排者）

- **本机跑不了 CI 那一格**：`npm run test:e2e` 在本机全绿，但「CI 在 `cf3051b` 上重新变绿」
  要等合并到 `feat/refactor-v2` 后由 GitHub Actions 验证（本票不推送）。
- **`b.clicks > 40` 是同类的隐患，但不在本票范围**：那是**出刀次数**（事件数，不是帧数），
  照样随机器速度浮动 —— 本机在 12.7fps 时点到 57 次（阈值 40，余量约 1.4 倍），
  降速 4× 时只点到 22 次。CI 按 13.7fps 估算余量还在，但**这是下一个会红的点**：
  如果 CI 再红，先看这条（把它改成「出刀次数 > 0」+ 让比例判据兜底即可）。
- **降速 10× 时（≈0.6fps）新判据会因保险丝报红**（`低于「没冻」保险丝 30 次`）——
  这是保险丝该有的行为：0.6fps 的测量窗口本身没有意义。真实 CI 是 13.7fps，余量约 13 倍。
