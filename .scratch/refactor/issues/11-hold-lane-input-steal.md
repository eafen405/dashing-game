# 11 — 长按怪与普通怪同轨导致该轨输入被吞

Status: resolved
Blocked by: (none)

## 现象

游玩中偶发「判定失灵」：普通怪已经进入判定区，点击对应半屏却没有出刀、不加分；
同一时刻该轨道上有一只长按怪（头部还没进判定圈）。

## 根因

`clearLane()` 在票 02 的「D1 修复」中改成只把**长按怪**算作轨道占用，
于是长按怪会被刷到一条已经有普通怪/双生怪的轨道上。

而 `pressLane()` 的优先级是：**该轨只要有长按怪，就先走长按逻辑**。
长按怪头部还没进圈时，按旧语义「不挥空刀」直接返回 —— 这次点击就被吞掉，
同轨的普通怪自然打不到。实测 200 秒模拟中，9~10 次长按怪刷新有 6~9 次与普通怪同轨，
每局累计 3~5 秒存在「进圈但点不动」的窗口。

旧 `clearLane()` 的 `some(!m.done)` 其实是正确的空轨判断：普通怪只占自己那条轨，
另一条仍会被返回；只有两轨都有怪时才返回 `null`，等下一次刷新再试。D1 属于误判。

## 修复

`src/game/rules/spawn.ts`：`clearLane()` 恢复「完全空轨」语义 ——
轨道上没有任何在场怪物（长按 / 普通 / 双生）才算空。
两轨都空时抽一次随机选轨；只有一轨空时直接返回该轨（不消耗随机）；
两轨都有怪时返回 `null`，本轮不刷长按怪。

长按怪因此始终独占一条轨道，`pressLane()` 的优先级不再会吞掉普通怪的输入。
刷新频率实测 900×405、正常游玩约 20–22 秒一只，仍符合 spec 的目标区间。

## 验证

- `spawn.test.ts`：一轨普通怪 → 选另一轨且不消耗随机；两轨普通怪 → `null`；
  长按 + 普通 → `null`；`spawnMonster()` 不会把长按怪刷进有普通怪的轨道。
- 200 秒 × 5 种子规则模拟：长按怪与普通怪同轨次数 **0**，
  「普通怪在判定区且同轨有长按怪」的帧数 **0**，长按怪 9~10 只 / 200 秒。
- Playwright：真实鼠标 / 键盘在普通区、暴击区、长按头部 / 1 秒 / 尾部均正常判定。
